# iOS 0.16.2.28

## 路口放大图：从「晚 2~3 秒」压到「半秒内」

问题现象：App 上已经出现路口图，圆屏要等 2~3 秒才出现，有时候过了路口才闪一下。

三个原因，都已修：

1. **分片排在底图后面**（主因）。路口图（bulk type 9）原来和普通底图一起按先来后到排队，
   圆屏一次底图是 600×600 的压缩流，几十上百片，路口图只能排在后面等。
   现在路口图和路线一样**插到队首**，只让当前那一片发完就让路。
2. **主线程被调试代码堵住**。高德回调里同步做了 `pngData()` + 透明检测（存 Caches 给人看的），
   一张千像素级 PNG 要几十到几百毫秒，这段时间 BLE 的发送循环也停着。
   这些全部挪到后台队列，主线程只留「拿图 + 立刻下发」。
3. **量化线程优先级太低**。`.utility` 会被系统限频，改成 `.userInitiated`。

顺带修掉「过路口后又闪回来」：`hide()` 会先作废还没发完的分片再让圆屏清图，
固件侧也有 2 秒静默窗兜底。同一个路口下次再经过还能重新下发（不再被像素哈希去重挡掉）。

## 建筑层：圆屏收不到能力位就整场降级

App 只有在确认圆屏支持建筑图层（`CAP,BLD,1`）之后，才会把带建筑的底图发过去；
没确认就把整张图降级成 legacy（去掉建筑索引），圆屏上就只剩路网。

- 固件 musicA.29 起，`CAP,BLD,1` 会跟着认证广播一起发，不再依赖 App 单次 `#GB?` 往返。
- App 侧探测次数 3 → 5、间隔 2 → 2.5 秒，只对旧固件生效。

所以这一版要配合固件 **musicA.29 或更新**才能看到建筑恢复。

## 其他

- 路口图有效期 45 秒 → 60 秒（红灯久等不会中途消失）。
- 版本号显示沿用 0.16.2.27 的改法（读 CFBundleShortVersionString），为 0.16.2.28，构建号 38。
