# iOS 0.16.2.131 — 路口放大图配色修复

基线 0.16.2.130。**固件不变**（musicA.141+ 都能用，包括当前实机的 .144）。

## 修了什么

路口放大图的路线色/箭头色会出现「蓝色路线变荧光绿、玫红箭头变粉紫、水面发紫」，串口里看调色板是 `route=1BFF00`、`arrow=C800AB` 这种明显不对的值。原因在 `CrossImageSender.saturateAccent`：

```swift
// h 本身已经是 0..6 的扇区单位（(g-b)/d 及其 +2/+4 偏移），
// 旧版又乘了 60，扇区绕了 6 圈 → 色相被随机映射到别的扇区
let hh = h * 60.0
```

修复：

- 色相不再从像素均值反推，改为**直接用 12 桶色相的桶中心**（`bucket*30+15°`）重建彩色槽，桶内平均带来的偏色也不会再让色相漂移；
- 扇区索引规范化（`0..5`），近灰像素不再原样返回灰色（那样彩色槽会退化成灰槽，路线直接消失）。

四个真实颜色的对照（同算法仿真）：

| 输入 | 0.16.2.130 | 0.16.2.131 |
|---|---|---|
| 路线蓝 `#2E7BFF` | `#1BFF00` 荧光绿 ❌ | `#0040FF` 蓝 ✅ |
| 玫红箭头 `#C83C5A` | `#C800AB` 粉紫 ❌ | `#C80032` 玫红 ✅ |
| 深蓝水面 `#1E4E7A` | `#680096` 紫 ❌ | `#007196` 青蓝 ✅ |
| 荧光绿地块 `#3CC828` | `#6400C8` 紫 ❌ | `#32C800` 绿 ✅ |

其余逻辑不动：4 档灰阶按亮度排序、彩色只量化到 4/5 两槽、彩槽保底亮度 150、蓝/青优先当路线、红/橙/黄优先当箭头。

## 兼容

- 不升级固件也能装，只是固件侧 `[CROSS] parse ok` 打印的 6 槽调色板仍是旧的错误值。
- 固件 musicA.144 起 `[CROSS] parse ok` 会打印全部 6 个槽，修好后应当看到 route/arrow 两槽落在正确色相。
