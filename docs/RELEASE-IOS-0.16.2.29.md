# MotoNav iOS 0.16.2.29

## 路口放大图改成两段式：先出预览，再补清晰全图

配合圆屏固件 **musicA.30**。

### 为什么改

实机串口测出来（带毫秒时间戳）：圆屏收到第一片到能画出来要 **1.4~2.1 秒**，
解析只占 0.11 秒，剩下全在等蓝牙——**每片固定 91~101ms**，跟包大小无关、只跟片数成正比。
这是手机锁屏时 iOS 主动把 BLE 连接间隔拉到 ~90ms 的结果，App 侧改不了。

所以不跟单包较劲，直接减片数：

1. **两段式**：先发 136×87 预览（片数约 1/4，0.4~0.6 秒上屏），再发 272×174 全图替换。
   骑行时体感从「等两秒」变成「几乎立刻出来」，随后自动变清晰。
2. **5 色量化**（原来是固定 16 色）：按本图实际亮度分布自适应挑 4 个灰阶 + 1 个彩色槽
   （保住蓝色路线、红色禁令标志）。深色化后本就接近无彩，合并中间调让同色游程变长，
   包体再降三成。

### 队列层面

`BleBulkWriteQueue` 的分片加了优先级：**预览 20 > 路口图全图 / 路线 10 > 底图 0**。
入队时插到「第一个优先级更低的分片之前」，并且预览那次入队才开闸（`pumpNow`），
保证队列顺序一定是 `[预览 5 片][全图 15 片][底图…]`，预览不会被全图抢在前面。

`hide()` 会同时作废 type 9 和 type 10 两批还没发完的分片，再发 `#CXH`。

### 兼容性

- 新 App + 旧固件（musicA.29 及更早）：type 10 会被丢弃，只剩全图，等于维持原来的节奏。
- 旧 App + 新固件：固件仍接受 `ver=1` 的 16 色包，不受影响。

### 验证

侧载后跑导航，圆屏串口应能看到：

```
[CROSS] parse ok preview 136x87 ...    ← 先到，立刻上屏（略糙）
[CROSS] parse ok full 272x174 ...      ← 随后替换成清晰版
```

App 的圆屏调试卡会显示 `已下发 预览XKB 全图YKB`。
