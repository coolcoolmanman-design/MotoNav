# MotoNav iOS 0.16.2.32（build 42）

配套固件：**musicA.35**（圆屏，建议一起升级）

## 修掉「相邻很近的两个路口，第二张放大图不显示」

实机反馈：连续两个近路口时，第二个路口的放大图来不及推到圆屏就不显示。
根因不是 BLE 传得慢（预览只有 5 片、0.4~0.6 秒），而是两层防抖把新图误杀了：

- 固件的 `#CXH` 后 2 秒静默窗**不分代**地丢掉所有整包，第二张预览正好撞进去；
- App 的 `hide()` 立刻 `cancelBulk(9/10)` + 发 `#CXH`。高德连续路口的回调可能是
  `show(新图) → hide(旧图)` 乱序，第二张刚入队就被清掉。

### 本版改法：延迟隐藏 400ms

`CrossImageSender` 新增 `pendingHide`（`DispatchWorkItem`）：

- `hide()` 不再立刻清队列和发 `#CXH`，而是延时 400ms 执行；
- 期间只要来了新的 `send()`（下一个路口的图），就 `cancelPendingHide()`，
  **取消隐藏、直接换图** —— 连续路口变成无缝切换，不再「退回小地图又冒出来」；
- 真过了路口（400ms 内没有新图）才照常 `cancelBulk` + `#CXH`。

`send()` / `repushCross()` / `onPaletteChanged()` 都走 `send()`，因此都会自动取消待隐藏。
400ms 的代价是过了路口后圆屏上的图多留 0.4 秒，骑行中几乎无感。

固件侧（musicA.35）同时把 2 秒静默窗改成**按路口代精确丢弃**：
`bulk` 头的 id 每发一张 +1，固件只丢与刚隐藏那代相同的迟到残包，
新代预览一到立即解禁、后续全图照常收。两端配合才能真正修好乱序场景。

## 没动的部分

- `#CXH` 命令格式不变，二进制 bulk 协议、`CROSS_W/H/PW/PH`（272×150 / 136×75）、
  `ver=2` 5 色调色板、昼夜双版配色、两段式（预览 type 10 → 全图 type 9）全部保持。
- 浮窗布局（272×150 @y96、圆角 6、昼夜描边）、车道胶囊位置均不变。
- 版本号仍由 `CFBundleShortVersionString` 读取，首页与关于页自动跟着 Info.plist 走。

## 实机看什么

找一段连续两个近路口（例如连续两个红绿灯）实测：

1. 第一个路口放大图出现 → 通过 → 第二个路口的图应在约 0.5 秒内换上来，
   中间不出现「退回小地图」；
2. 两个路口都能看到预览（略糙）随后变清晰全图；
3. 已过最后一个路口约 0.4 秒后，浮窗收回、退回小地图；
4. 圆屏串口若打 `[CROSS] 新一代路口图 gen=X（隐藏的是 Y），解除静默`，说明按代放行生效。
