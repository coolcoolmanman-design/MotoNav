# MotoNav iOS 0.16.2.45

基于 ui.4 / iOS 0.16.2.44 的导航结束状态修复。配套固件 `7.12.10-ui.2-zelda40.9-musicA.49-ui.5`，
建议两端一起升级；只升级一端也能改善（固件侧有独立兜底）。

## 问题

导航结束后（退出导航或到达目的地），圆屏先回待机页，过几秒又自己切回导航页面，
且「目的地剩余距离」显示 0。

## 根因

**不是「手机端设置的目的地没清除」。** `NaviBridge.finish()` / `resetState()` 确实保留
`destLat/destLng/shareRoute/routeReady`（只有换目的地时 `clearPlan()` 才清），但它们只影响
主页的「重新规划 / 再跑一次同一路线」，不会向圆屏发导航帧，不是直接触发点。

真正原因是 BLE 状态补发与发送队列残留：

1. `BleLink.onLinkReady()` 在断连重连时整批补发 `lastState`。到达链路自 0.16.2.13 起
   刻意不发 `C`（为了保留圆屏到达庆祝与设备端 OK），于是 `lastState["NAV"]` 长期停在
   `"A,0"`，重连被原样重放；固件收到 `A,0` 就 `inNav=true / navDist=0`。
2. `BleLink.send("C")` 原先只清队列里的图片项（`B*`），排队的 `L,120` / `#e,0,...` 等
   导航尾帧会在 `C` 之后才写出（BLE 写有 pacer），看起来就是「过一会儿自己回去了」。
3. 网页路线到达同样发 `A,0` 而不发 `C`，路径相同。

## 修复

- `BleLink.swift` 新增 `dropNavigationTransient()`：会话结束时清掉 `lastState` / `stateOrder` /
  发送队列里的导航瞬时帧（`NAV`、`#e/#p/#v/#g/#k/#c/#j/#u/#x/#y/#h/#o/#J` 与 `#O...`）。
  只清缓存，不向圆屏发任何命令，避免抢关到达庆祝和 OK。
- 到达帧 `A,0` 与行程统计 `#O...` 改为一次性帧，不再写入重连缓存（当次照常发送）；
  顺带避免历史行程统计在 `lastState` 里越攒越多。
- `NaviBridge.finish()` 在发行程统计 / 结束帧**之前**调用清理（顺序不能反）；
  `resetState()` 改为退出与到达都执行，顺带修掉「上一趟 `lastSent` 残留导致下一趟第一帧
  被去重吞掉」。
- `WebMotorSession.stop()` 同样调用清理，覆盖网页路线导航。
- 巡航 `#z`、进度开关 `#M1/#M0` 等持久状态保留；导航途中重连仍靠 `NAV` 缓存恢复画面，
  清理只在会话真正结束时发生。

## 兼容

- 协议零改动，没有新增或修改任何 BLE 命令；旧固件 + 新 App、新固件 + 旧 App 都能工作。
- 开机动画、卫星图空白修复、GTA 下半动画、路口放大图、动态背景 / 六槽 / 时间样式等
  ui.4 功能一律不动。
- 目的地与路线计划保留在主页，到达后仍可「重新规划」或直接再跑一次同一路线。

## 验证建议

退出导航、到达目的地（含网页路线 / 模拟导航）、点圆屏 OK、不点 OK 等 60 秒兜底、
导航中锁屏 / 切后台再回来触发重连——圆屏都应停在待机页，不再跳回「剩余 0」的导航页。
