# 固件 7.12.10-ui.2-zelda40.9-musicA.75

基线 musicA.74。配套 iOS **0.16.2.68**，两份 release 都保持 draft，不 publish。
落地 FO-225b 确认稿的 **B 方案**：新增音乐主题 7「封面流 Cover Flow」，由 App 预下发 3 张 64² 真专辑封面（bulk type 12），固件做真透视卡组 + 卡带短拖 + 松手吸附。不开机动画下拉框、不加 App 特效开关、不加惯性甩动、无新增位图资源。

## 为什么必须有新协议

现状主题 1「封面轮播」只有 `coverImg`（当前 128²）与 `coverPrevImg`（上一首），AMS 拿不到播放队列的下一首封面，右侧卡只能用当前封偏色伪造 —— 正是被吐槽的点。B 方案按确认稿要求「3 张不同专辑的纵深」，所以 App 侧新增轻量预下发：进入音乐页 / 切歌 / 重连时把 3 张 64² 缩略封推到圆屏，**不能等滑动时实时取**（BLE ≈5 KB/s）。

- bulk **type 12**：`'C''F''Q' ver=1 count` + `count × { slot(u8), zlen(u16 LE), zlib(64² RGB565 LE) }`。
- slot `0=上一首 / 1=当前 / 2=下一首候选`；允许只发 1~2 个 slot 做增量刷新。
- 固件 `parseCoverQueue()` 用独立 tinfl 解压到 3 块 64² PSRAM（24 KB），失败也回 `K,12,<id>`，App 侧兜底重发；收到有效包把 `cfShift` 归零、`musicDirty` 整页重画。
- **数据口径**：iOS AMS 仍拿不到真实「下一首」封面，slot 2 由 `CoverQueueBridge` 用最近播放历史 / 本地曲库另一张专辑的真封面填充；手机真的切歌后推来新封面并重发队列，圆屏自动对齐。老版本 App（无 type 12）退回 3 张不同色调的渐变占位，不会黑屏或崩。

## 主题 7 的绘制与手势

几何逐像素沿用已确认的 `motonav-coverflow-b.png` / `motonav-gesture-strip.png`：中央 164² @ (233,170)、右一 54×144 @339、左一 36×140 @131、倒影 34px、7 个卡位远→近循环复用 3 张真封。

- **逐列 16.16 定点梯形采样**：每列只算一次 `u`、顶/底边收敛、`v` 步长，像素内部全是乘加；左右边竖直 + 上下边向远侧收敛近似 `rotateY`，近侧提亮 / 远侧压暗走 `musicDim565()`，圆角与圆屏 `chordHalf` 同处裁掉。无 GPU、无纹理、无逐像素除法。
- **局部脏矩形 318×220 @(74,76) = 70k px**：整页重绘时先 `cfCaptureBand()` 存一张干净背景带，拖动帧只恢复这条带 + 重画卡组 + `flushRect()` 局部推屏；文字 / 进度 / 播控全在带外，静止时 **0 重绘 / 0 BLE**。按像素量外推约 22 fps（非实测），瓶颈是 SPI 推屏而非采样或 83 Hz 触摸。
- **手势分区**：`dragMove()` 里只有 `page==2 && musicStyle==7`、按下点换算到画布后落在 `y 88..286`、且为横拖并超过 12~16 px，才判给卡组相位；`touchY0` 与点按一样过 `touchVectorToCanvas()`（`TOUCH_FLIP_Y` 会上下镜像）。**卡带外 / 竖拖 / 其他主题的原换页逻辑一字不改**（仍是 `dragTarget=0` 与 36 px 阈值）。
- **吸附**：松手 `cfSwallowTap` 吃掉这次点按，7 帧 `ease-out = 1-(1-t)³` ≈315 ms 按格对齐；不足一格回弹到 0；最后一帧本地队列滚一格并真的发 N/P（HID / AMS / legacy 三条路径与 `musicTap` 一致），随后手机重发队列归位。拖动与吸附期间 `musicTick()` 提前返回，暂停唱片旋帧与 500 ms 进度刷新，避免把卡组弹回 phase=0。
- 点左右侧卡也能切歌（`musicButtonAtStyle()` style 7 分支），这是零冲突、最稳的一档。
- `#MS` 上限 `0..6 → 0..7`；`MotoNav.ino` 开机读 NVS 的 `mstyle` / `bg_sty` 取模由 `% 6` 改成 `% 8`，顺手修掉 FO-218 黑胶(6)、FO-220 像素白天(7) 重启后丢样式的问题。

## 已知限制（实机重点看）

1. **装车旋转退化**：`fastPushRect()` 在 `rotFree || screenRot != 0` 时直接 return false，局部刷退回整屏 `flushSync()`（约 12 fps、跳帧顿挫）。若圆屏装车后旋过角度，观感会明显变差，需另做旋转友好的分块推送。
2. **歌名文字仍由手机位图下发**（`imgs[5/6]`），滑动吸附完成后到 AMS 推来新文字之间有短暂空窗，这段时间中央已是候选封面但文字仍是上一首；不做本地伪造文字。
3. 卡带热区按画布坐标判定，90° 旋转时 y 会映射到 x，热区失效（与限制 1 同源）。
4. 3 张真封是「历史 / 当前 / 候选」，不是真实播放队列的顺序；这是 iOS AMS 的数据边界，不是固件缺陷。

## 编译与体积

本地 `python firmware/build.py --cli ... --jobs 8`：**Flash 2,949,391 B（93%）/ RAM 145,444 B（44%）**，相对 musicA.74（2,944,291 B / 144,844 B）增加约 5.1 KB / 600 B，Flash 余量仍约 196 KB。零新增 Flash 位图，24 KB 队列缓冲全在 PSRAM。

## 建议实机验证

1. 刷本版 + 侧载 0.16.2.68，音乐样式下拉框选最后一项「封面流 Cover Flow」，圆屏回执 `MS,7`；开机日志看 `[CFQ] slots=3 ok=111 shift=0`。
2. 静止画面：中央 164² 当前封、左右各一张**不同**专辑的透视卡、34 px 倒影、歌名 / 作者 / 进度 / 白圆播控都在圆屏安全区内，不被圆弧切掉。
3. 在卡片带内横拖约 60~100 px：卡片连续换位而非整张位图平移；松手后按格吸附、无惯性甩动，最后一帧发切歌并等手机推新封面。抓 `[CFQ] drag start` / `[CFQ] release` / `[CFQ] snap` 与 `[MUSIC] fps`（本版暂未打 fps 日志，可用屏保同款计时手段复核）。
4. 卡带外滑动 / 竖拖仍回主页；短拖松手不能误触发播放或切歌；点左右侧卡可切歌。
5. 切回 style 0..6、进导航 / 屏保 / 动态背景 style 6、7，确认没有回归；重启后所选音乐样式与动态白天仍能恢复（取模修复）。
