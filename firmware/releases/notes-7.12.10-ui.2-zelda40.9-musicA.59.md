# 固件 7.12.10-ui.2-zelda40.9-musicA.59

基线 musicA.58 / iOS 0.16.2.56（`3e71b00` · Draft
`untagged-477a7a9ca1851a873c21`）。配套 iOS **0.16.2.57**。
本版在 58（C Infograph 全屏指针）之上补入矢量简图周边路网，58 的功能全部保留。

## 矢量简图（样式 13）补周边路网

- 新增 `vhDrawRoadNet()`：复用 `drawMapFrame()` 同一套视图变换
  （`predictPose` + GPS 平滑 + `viewHdg` 时间平滑 + 随车速缩放）、
  `featBox` 视口裁剪、`mapPolyline` 折线渲染
- 在 `vhDrawFullRoute()` 画主路线**之前**调用 → 路网永远在主线下面，
  主线白描边 + 主色内芯照旧压最上层
- 线宽 `{0, 16, 12, 8} × wk`（wk = sc/0.6，与主线 13×wk 同比，缩放时比例不变）
- 夜 `#2A3745` / 昼 `#C3CCD6`，与现有带底图样式道路同色
- 无要素、或要素帧与当前定位帧不对齐时自动不画，退化成 musicA.57 的观感
- HUD 让位保持 `vhFadeRect()` 半淡化，路网在文字下仍隐约连续

## 数据来源

路网要素走固件既有的 bulk type 1（`parseMap()` / `mapShow` / `featCls`），
协议零新增。要素由 iOS 端从高德栅格底图的道路标签层（`PX_ROAD = 1`）
矢量化后下发，约 10 KB 级（栅格原包 100 KB 级，不再上 BLE）。

## 兼容

- 老 App（发栅格 type 3）连新固件：样式 13 不画路网，等同 musicA.57
- 新 App 连老固件：老固件忽略 type 1 要素包，样式 13 仍是纯主路线
- C Infograph、A/B、时钟、组合精灵、路口图隐藏等 58 及之前的行为全部不变

## 建议实机验证

- 样式 13 导航中：主路线完整、周边灰色道路可见且不抢主线、路口处线连续
- 缩放（车速变化）时灰线与主线的粗细比例是否稳定
- 停车/低速时路网是否不发抖；HUD 文字区域是否仍然可读
- 回到样式 1..12：底图栅格、路口放大图、车道条是否与 58 一致
