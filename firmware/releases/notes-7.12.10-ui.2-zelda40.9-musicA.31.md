# MotoNav 固件 7.12.10-ui.2-zelda40.9-musicA.31

## 一、屏保把「不插电闲置关机」短路了（修复）

待机页静置 60 秒进屏保，而主循环里屏保分支是**提前 return** 的，`loop()` 末尾那段闲置关机判定
（原来是每分钟才轮到的那个位置）就再也跑不到。结果：不插电放着，进屏保之后永远不会自动关机，
电池一路耗到底。

- 判定抽成 `idlePowerOffTick()`，屏保循环里也调一次，两条路径共用同一套计时。
- 时长本来就是这个值：`IDLE_POWER_OFF_MS = 300000`（**5 分钟**，上游 7.12.1 定的）。
  如果你实测到「两分钟就关」，那更可能是电池真的到欠压保护线了，不是这个计时器。

## 二、App 圆屏 tab 电量显示「—」（修复）

三个原因叠在一起：

1. **屏保里不轮询电量**。`batPoll()` 在屏保那段提前 return 之后，屏保期间一次都不跑，
   手机只连不发，App 侧 `screenBattery` 永远停在 nil → 显示「—」。
2. **连上后不立刻推**。以前只在「电量变化」或「60 秒心跳」时发 `V,...`，
   刚连上那段时间（尤其设备停在屏保里）就是空的。
3. **油量计越界被当成没电池**。AXP2101 的 0xA4 在快没电 / 刚上电时偶尔返回 0xFF 之类，
   旧逻辑直接判成 -1 发出去。现在只要电池在位，就用电压按锂电放电曲线估一个（3300~4200mV 分段插值）。

改动：

- 屏保分支补 `batPoll()`；`batPoll()` 在屏保期间不再去重画状态栏（以前会糊到屏保画布上）。
- 手机认证通过时置 `batPushNow`，下一次轮询立刻补推一条 `V,...`。
- 油量计无效但电池在位 → 电压估算；估算仍为 0 时按 1% 上报（0% 容易被当成已关机）。
- 新增串口日志：`[BAT] pct=9 mv=3717 chg=1 usb=1`（只在数值变化时打，不刷屏）。

## 三、路口图插队规则（修 CI 回归）

`BleBulkWriteQueue.replace` 加了分片优先级后，只给 `prioritize` 不给具体优先级的调用
（时钟 `#TIME` 这类一次性命令）会被排到队尾，`ios/tests/ble-bulk` 里那条
「Unfragmented clock command receives the next acknowledged ATT slot」直接 precondition 失败。
现在 `prio` 缺省为 -1 = 老语义「插到队首」，只有给了 10/20 才按优先级比较。
