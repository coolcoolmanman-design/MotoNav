# MotoNav 固件 musicA.95 · 开机动画雷电版 + 申花双帧返工终版 + WiFi 地图加速回归

> 配套 iOS **0.16.2.86**（本版建议一起升，WiFi 开关在 App 里）。基线 musicA.94。**musicA.84 仍不安全，勿刷。** Draft 保持。

## ⚠️ 分区表变更（重要，先看这条）

WiFi 地图加速引入 lwIP + esp_wifi + wpa_supplicant，固件从 3,028,075 B 涨到 **3,586,375 B**，
**超出原 3MB app 分区 440KB**，链接直接失败。本版把 app 槽从 3MB 扩到 **4MB**：

```
nvs      0x9000    20KB      (不变)
otadata  0xe000     8KB      (不变)
app0     0x10000   4MB       ← 由 3MB 扩
app1     0x410000  4MB       ← 由 3MB 扩 + 偏移后移
ffat     0x810000  7.875MB   ← 由 0x610000/9.875MB 前移并缩小
coredump 0xFF0000  64KB      (不变)
```

新 app.bin 上限 **4,194,304 B**（旧版 3,145,728 B）。

**刷机必须先写分区表，再写 app**，否则旧的 3MB 表会让新固件启动失败：

```
esptool --chip esp32s3 --port COM5 --baud 921600 write_flash \
  0x8000  MotoNav_universal_1.75_v7.12.10-ui.2-zelda40.9-musicA.95_panel0_partitions_0x8000.bin \
  0x10000 MotoNav_universal_1.75_v7.12.10-ui.2-zelda40.9-musicA.95_panel0_app_0x10000.bin
```

- `0x8000` 只写分区表（3,072 B），**不会碰 NVS**（NVS 在 0x9000），设置/凭据保留。
- **不要用 `full_0x0.bin`**：它会把 0x9000-0x10000 全刷成 0xFF，NVS（WiFi 凭据、用户设置）会丢。
- 分区移动后 ffat 里的壁纸/吧唧缓存失效，固件会自动重新 format，App 重推即可。

## 本版

- **申花开机动画改为「雷电版」实时绘制：**
  - 资源仍只有 **1 张静态徽章帧（5,871 B）**，效果全部代码绘制，零额外 Flash 占用。
  - 徽章 1s 从**纯黑**淡入（轻微缩放沉降），由闪电逐次劈亮；无光晕圈、纯黑背景。
  - **14 轮斜劈闪电**（锯齿主干 + 分叉 + 闪烁，从画布边缘劈到盾徽轮廓，命中点实时轮廓检测）。
  - 盾徽周缘 **爬行电弧**（每 2 帧重生成）、主雷间隙背景微闪电填充、命中火花 + 辉光。
  - 两轮**大雷**整屏偏蓝加法泛光；总时长 3.2s。每次开机形态随机（esp_random 种子）。
  - 品牌 ID 19 / 命令协议不变。
- **中央动画（待连接 / 已连接）返工终版：**
  - 待连接态改「**E 档**」：第二轮加强降红（红 sat×0.62 / val×1.08）——94 实机反馈仍偏红。
  - 已连接态改「**v2**」：骑手头发改近黑深梅色（全覆盖映射，不再与围巾/披风混色）；整体场景右移 16px 腾出拖行道；**绳索从后轮毂连到红人腰部**（带垂弧）；轮子与红人之间加扬尘、地面拖痕；红人逐帧颠簸模拟拖行——修复 94 实机反馈的红人割裂感。
- **WiFi 地图加速（试验功能回归）：**
  - 圆屏开 SoftAP，手机 HTTP PUT / TCP 7443 整包传 type3 底图，BLE 仍管控制/路线/确认。
  - 固件新增 `WifiMapReceiver`（SoftAP + TCP 收包 + HTTP 探测），命令 `#WIFI,1 / #WIFI,0 / #WIFI?`。
  - 这是本次 app 槽扩到 4MB 的唯一原因。
- **唱片转速提速**：全屏 12s/圈、黑胶 8s/圈，刷新 28fps。
