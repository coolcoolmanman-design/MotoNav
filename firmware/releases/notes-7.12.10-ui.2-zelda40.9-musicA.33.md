# MotoNav 固件 7.12.10-ui.2-zelda40.9-musicA.33

配套 iOS：**0.16.2.31**（本版无需升级 App，见文末兼容性）

## 车道胶囊移到路口放大图下方

参考竞品圆屏的路口画面，放大图下方还有一条黑色车道胶囊，白色车头三角从胶囊下沿露出，
纵向是「图 → 胶囊 → 车头」三段式。我们此前的做法不同：

- `drawMapLanes()` 把车道条画在 `y=100~130`（有测速牌时 `114~144`）；
- 路口图浮窗 `y=96~246`，且 `drawCrossOverlay()` 是 `drawMapFrame()` 里最后一步；
- 车道条先画必然被浮窗盖住，所以 musicA.28 起干脆 `if (crossReady()) return;` 主动不画，
  注释理由是「高德路口图位图里本来就有车道」。

结果路口图出现时车道指示整条消失，和参考设计的信息分层不一致。

### 本版改法

把车道绘制拆成两条路径：

| | 非浮窗模式 | 路口图浮窗模式 |
|---|---|---|
| 函数 | `drawMapLanes()`（`MapHud.h`） | `drawCrossLanes()`（`MapHud.h`，由 `drawCrossOverlay()` 末尾调用） |
| 时机 | HUD 阶段，浮窗之前 | **浮窗之后**，保证压在最上层 |
| 高度 / 限宽 | 30 / 210 | **24 / 140** |
| y | 100（或 114） | **234**（`CROSS_Y + CROSS_H - 12`） |
| 避障框 | `addHudObstacles()` 原位置 | 同步到新胶囊位置 |

浮窗下沿 246 到车头 `MAP_PY=262` 只有 16px，放不下 30px 高的常规胶囊，
所以缩小并向上压进卡片 12px；车头三角（约 244~276）从胶囊下方露出约 14px，
与参考实拍的「三角尖从胶囊下沿冒出来」一致。`MAP_PY` 是导航前视偏置，未改动。

三个新常量集中在 `MapState.h`：`CROSS_LANE_H / CROSS_LANE_MAXW / CROSS_LANE_Y`，
`drawCrossLanes()` 与 `addHudObstacles()` 共用，避免两处数值走偏。

## 兼容性

- **只改固件，App 不用升级**：路口图尺寸仍是 `272×150` / 预览 `136×75`，
  bulk type 9/10、`ver=2` 协议（5 色 + nibble RLE）全部未动。
- 刷机后仍是 `0.16.2.31`，`CROSS_W/H/PW/PH` 两端保持同步。
- 车道胶囊只在 `laneN > 0 && ringActive`（转弯倒计时生效、有车道信息）时出现；
  没有车道数据时不会留一块空黑条。

## 实机看什么

进入导航、接近有车道信息的路口，等路口放大图浮窗出现后确认：

1. 卡片下沿中央有一条黑色圆角车道胶囊，白/灰车道箭头可读；
2. 白色车头三角从胶囊下方露出，没有被完全盖掉；
3. 胶囊没有压住卡片里引导路线的关键部分（压入 12px，若觉得偏多可调 `CROSS_LANE_Y`）；
4. 过了路口浮窗收回后，车道条回到原来的顶部位置（`y=100/114`）、高度恢复 30。
