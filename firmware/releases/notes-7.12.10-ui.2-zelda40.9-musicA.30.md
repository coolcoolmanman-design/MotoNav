# MotoNav 固件 7.12.10-ui.2-zelda40.9-musicA.30

## 路口放大图：先到预览，再补全图

上一版实测（串口带毫秒时间戳）：一圈路口图从圆屏收到第一片到能画出来要 **1.4~2.1 秒**，
其中解析只占 0.11 秒，剩下全是在等蓝牙。每片固定 **91~101ms**，跟包大小无关、只跟片数成正比——
手机锁屏时 iOS 会把 BLE 连接间隔拉到 ~90ms，一片一个连接事件，十五六片自然就是两秒。

这一版从「片数」下手，两条一起：

- **两段式**：App 先发一张 136×87 的预览（片数约 1/4，0.4~0.6 秒上屏，圆屏 2 倍放大、略糙但够认路），
  全图随后替换成清晰版。骑车时不再是「等两秒、过了路口才闪一下」。
- **16 色 → 5 色**（4 级灰 + 1 个彩色槽）：深色化之后本来就接近无彩，合并中间调让同色游程变长，
  包体再降三成，片数跟着少。

## 协议变化（App 必须同步升级）

```
'X'(0x58) | ver=2 | u16 w | u16 h | 16 × u16 RGB565（前 5 个有效）| nibble RLE
```

- `ver=2` = 5 色；`ver=1`（旧的 16 色包）仍然接受，老 App 不会突然黑屏。
- 尺寸决定走哪块缓冲：**272×174 → 全图（bulk type 9）**，**136×87 → 预览（bulk type 10）**。
- 其他尺寸一律拒收，串口会打 `[CROSS] parse: 尺寸 ... 不认识`。

## 串口日志

```
[CROSS] rx start type=10 id=7 total=2103 parts=5     ← 预览开收
[CROSS] parse ok preview 136x87 2103B ver=2 ...     ← 预览可画
[CROSS] rx start type=9 id=7 total=6431 parts=14    ← 全图开收
[CROSS] parse ok full 272x174 6431B ver=2 ...
[CROSS] overlay on (full crossAt=... prevAt=...)
```

`overlay on` 里会标当前显示的是 `preview` 还是 `full`，直接能看出两段各自什么时候上的屏。

## 兼容性

- 新固件 + 旧 App（0.16.2.28 及更早）：仍按老协议收 16 色全图，功能不受影响。
- 新 App + 旧固件（musicA.29 及更早）：type 10 会被直接丢弃，只显示全图，也是全图的老节奏。
