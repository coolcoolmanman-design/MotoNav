## 问题：不是屏幕彩边，是代码画的彩色点串

用户实机反馈屏保眼睛边上有「很细的蓝色和红色细线做点缀，太细不美观」。定位在 `Screensaver.h::svDeco()`：

- `SVD_TRAIL`（球面转头 / 惊跳尾迹）：三条弧用 `fillCircle(..., 2, ...)` 逐点画，青 `0x6EB9` / 粉红 `0xFBD2` / 灰蓝 `0x6BF2`，角步长 0.07rad ≈ 7px 点距，而圆点直径只有 5px —— 是**断续点串**，不是实线。
- `SVD_ORBIT`（轨道环绕）：同规格点串扁椭圆 + 一颗 r9 粉红亮点。
- `SVD_RAYS`（兴奋 / 惊跳闪线）：两眼外侧 4px 灰蓝竖线，紧贴眼睛像划痕。

根因是空间不够：脏矩形上沿 132 到眼睛上沿 160 **只有 28px 头顶高度**，而三条弧半径 96 / 111 / 126 又都挤在这条带里，点串互相叠成一条**锯齿状彩边**；屏保亮度压到待机的 45% 后彩色细线更容易发糊。

## 方案 B：全部收敛到中灰连续实线

确认稿 `saver-deco-before-after.png` / `saver-deco-compare.png`（`sim-saver-deco.py` 按固件 466×466 物理像素 1:1 仿真）。四套候选里选 B「统一中灰 + 加粗」。

| 位置 | musicA.73 | musicA.74 |
|---|---|---|
| 头顶尾迹 | 三条彩色点串弧叠成彩边 | **一道 7px 中灰实线弧 + 两端 r5 亮灰圆点** |
| 轨道 | 断续点串椭圆 + 粉红亮点 | **5px 连续实线圈 + r10 亮灰点** |
| 闪线 | 4px 灰蓝竖线 | **8px 中灰实心短棒** |
| Zzz / 小心 / 汗滴 / 斜眉 | 灰蓝 / 粉红 / 青 | **统一中灰** |
| 三点脉动 / 感叹号 | 白色（主体动效） | **不变** |

实现要点：

- 新增 `svArcStroke(cx, cy, rx, ry, a0, a1, step, r, c)`：用**密集圆点串**（点距 < 直径即连成等宽实线）画连续弧 / 椭圆，比逐段粗线省一半绘制指令。尾迹 `step=0.035 / r=3`，轨道 `step=0.035 / r=2`。
- 颜色常量删掉 `SV_DIM_C` / `SV_ACCENT_C` / `SV_CYAN_C`，全装饰复用眼睛羽化外圈已有的 `SV_EDGE_C 0x8C71`（中灰），只新增 `SV_HI_C 0xBDF8`（亮灰）给小圆点提层次。屏保回到「纯黑白脸 + 中性灰点缀」，不再出现任何彩色细线。
- **刻意只留一道弧**：试过把三条弧各自加粗到 6px，结果粘成一条粗眉，比彩边更难看；头顶 28px 放不下三条粗线，所以改成单弧 + 端点。
- 所有坐标仍在原有脏矩形 **74..392 / 132..300** 内，没有扩大局部推送区域。

## 保持不变

45% 亮度 + 40~120 夹紧 + 320ms 渐变、4px / 180s 防烧屏漂移、30fps 目标、IMU 四层互动、触摸只唤醒、16 表情 + 8 动效的调度与决策优先级、`#SV` 屏保总开关、**App 侧没有任何新开关或新命令**。零位图、零额外 Flash 资源，纯代码绘制。`DynamicBg.h` 的夜 / 昼双主题一行未动。

## 编译与体积

本地 `python firmware/build.py --cli ... --jobs 8`：**Flash 2,944,291 B（93%）/ RAM 144,844 B（44%）**，
相对 musicA.73（2,944,327 B / 144,844 B）反而少 36 B —— 三条彩色弧并成一道、点串循环合并成 `svArcStroke()`，代码量净减。Flash 余量仍约 200 KB。
本次每帧绘制的圆点数略增（轨道 70→179、尾迹 111→53），实机重点看 `[SAVER] fps=` 是否仍约 30。
