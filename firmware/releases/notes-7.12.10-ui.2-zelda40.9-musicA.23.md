# MotoNav 固件 v7.12.10-ui.2-zelda40.9-musicA.23

## 新增：待机屏保（程序化眼睛动画）

待机页静置 **60 秒**无操作后自动进入屏保：纯黑背景上出现一双会呼吸、会眨眼、
会四处看的眼睛。任意触摸或按 PWR 键立即唤醒，回到原来的待机页。

### 触发条件（全部满足才进入）

- 停在待机页（`page == 0`），不在音乐页 / 天气页 / G 页 / 胎压页
- 没有导航（`inNav` 为假），也没有来电、配对码、电源菜单、滑动、到达动画
- 没有息屏
- 60 秒内没有触摸、没有按键、没有导航信息传入
- **BLE 心跳不算活动**：只有真正的触摸 / 按键 / 导航帧会重置计时

### 唤醒

- 触摸：只唤醒，不产生任何手势（那一次点击被吃掉，不会误触发换页或按钮）
- PWR 键：短按照旧息屏，长按照旧弹电源菜单
- 导航帧到达：立刻退出屏保，直接进导航画面

### 动画内容

| 动作 | 参数 |
|---|---|
| 呼吸 | 约 0.18Hz，幅度 ±1.6% |
| 眨眼 | 280ms（95ms 闭合 / 30ms 保持 / 155ms 睁开），间隔随机 3.4–6.2 秒，偶尔连眨两下 |
| 扫视 | 五个观察方向随机切换，停留 2.5–5 秒 |
| 微扫视 | 每 0.8–1.7 秒一次轻微抖动，避免完全静止像死机 |
| 2.5D 头转 | 转向侧眼睛略大、眼距压缩、整脸横移，俯仰带动眼睛上下 |

### 实现要点

- **纯代码绘制，不含任何图片资源**：466×466 一帧 RGB565 就是 434KB，存几十帧要几十 MB，
  解码加整屏推送只能到约 12fps。改成代码画眼睛后，固件只增加 2.7KB Flash、144 字节 RAM。
- **局部推送**：新增 `fastPushRect()` / `flushRect()`，只把眼睛所在的 316×164 脏矩形推到屏幕
  （101KB/帧，40MHz QSPI 理论 5.2ms），目标 30fps。整屏推送则只有约 12fps。
- **AMOLED 防烧屏**：画面做 4px 半径、180 秒一圈的极缓慢漂移；屏保亮度降到 55（正常 200），
  退出时恢复用户设定亮度。
- **不阻塞蓝牙**：屏保判断放在消息处理之后，BLE 消息照常入队处理，只是不绘制页面。

### 边界处理

- 屏幕处于旋转状态（非 0° 或是任意角度）时，局部推送取不出矩形，自动退回整屏推送。
  功能正常，只是帧率降到约 12fps。
- 屏保期间不刷新电量、不刷新天气，退出时统一重画当前页。

## 已知限制

- 当前只实现了 `idle` 一种状态（呼吸 / 眨眼 / 扫视）。原参考项目另有 11 种交互表情，
  但屏保状态下用户并不在场，触摸会直接唤醒，因此交互表情暂时不做。
- 屏保期间 CPU 占用高于正常待机（30fps 连续绘制），但 AMOLED 纯黑区域不发光，
  屏幕功耗反而低于显示待机页时。
