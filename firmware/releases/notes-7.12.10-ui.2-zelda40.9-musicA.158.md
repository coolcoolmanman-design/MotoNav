# MotoNav firmware musicA.158

配套 iOS：**0.16.2.136**（无需升级）

## 相对 .157 的变更

### 1. 帧率：外圈两条弧带重写（HUD 最大头）
`.157` 的 `HUDT` 分段计时实测（密集立交场景，n=13~14）：

| 段 | ms/帧 |
|---|---|
| 时间 | 1~2 |
| 大距离 | 4~7 |
| 单位 | 1 |
| 转向箭头 | 2~4 |
| 车速圆 | 4 |
| 右侧红徽 | 2 |
| 底胶囊 + 路名 | 9 |
| 指南针 + 车道 | 2~3 |
| **双环（倒计弧 + 行程弧 + 5 段流光）** | **21~27** |
| HUD 合计 | 约 47 |

`arcBand()` 原来按整个圆环扫每一行、再逐像素用两条半径线丢弃（125° 弧白算约 65% 的像素，每像素还带一次 `sqrtf`）。
现在先用两条半径线的半平面把该行 x 区间裁到扇形内，再逐像素做 AA。**视觉公式一个字没改**（`e0/e1/r/a` 全同），已用 Python 逐像素比对确认 0 差异（2849 px 完全一致）。

### 2. 触摸划动失效（导航中）
`slidePrepare()` 需要两块 434KB 的 PSRAM 缓冲。导航时 PSRAM 很紧（两块瓦片缓冲 + 8 块软掩膜 + 动态背景），分配失败时原实现**直接 return false**，手势被静默吞掉 —— 就是「导航过程中怎么划都不换页」。
现在分配失败时退化成立即切页（无滑动动画，但一定换得过去），并打 `[SLIDE] no buffer ... psram_free=...` 日志。

### 3. 诊断增强
`RAST` 行追加 `psram=KB`，可看到导航时的 PSRAM 余量。

## 实测参考（.157，COM5，密集立交场景）

- `FPSSTAT`：6.4 fps，帧周期 156ms，mapDraw 84 / flush 91 / ras（3D 瓦片重采样）64
- `HUDT`：47ms（其中双环 21~27）
- `RAST`：`v=1 age=15~20ms ins=4 rej=0 blank=0`（瓦片正常、无空白块被挡）

> 注：3D 瓦片透视重采样（`ras` 64ms）本身就是最大单项开销，但它换来的是整屏真实路网细节，**换成矢量 3D 建模不会更快**（见发布说明讨论）。
