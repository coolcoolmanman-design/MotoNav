# MotoNav 固件 7.12.10-ui.2-zelda40.9-musicA.34

配套 iOS：**0.16.2.31**（本版无需升级 App）

## 车道胶囊上移 10px，给车头箭头和引导线让位

musicA.33 首次把车道胶囊放到路口放大图下方，实机反馈「导航箭头有些挡」：

- 当时 `CROSS_LANE_Y = 234`，胶囊底衬画到 `y=262`，正好压在车头 `MAP_PY=262` 上；
- 白色车头三角本体约 `244~276`，只剩 `262~276` 一截梯形底露出，尖端被盖掉，看着不像箭头；
- 车头前方的引导线也一并被压住。

本版把 `CROSS_LANE_Y` 从 234 上移到 **224**（`CROSS_Y + CROSS_H - 22`），其他一律不动：

| | musicA.33 | musicA.34 |
|---|---|---|
| 胶囊 glyph | 234~258 | **224~248** |
| 半透明底衬 | 230~262 | **220~252** |
| 压进卡片 | 12px | **22px** |
| 车头三角露出 | 约 14px（只有梯形底） | **约 24px（尖端接近完整）** |

底衬到 252 就收住，`252~262` 这段车头前方的引导线露出来一点；
胶囊是 `dimRect(..., keep=70)` 半透明黑底，多压进图片的 10px 仍能隐约看到下面的图。

`drawCrossLanes()` 与 `addHudObstacles()` 共用 `MapState.h` 里的三个常量，
所以绘制位置和电子眼避障框一起同步，不会出现「图移了、避障没移」。

## 兼容性

- **只改固件，App 0.16.2.31 不用升级**：路口图尺寸 `272×150` / 预览 `136×75`、
  bulk type 9/10、`ver=2` 协议（5 色 + nibble RLE）全部未动。
- 胶囊高度 `24`、限宽 `140` 不变，只在 `laneN > 0 && ringActive` 时出现。
- 非浮窗模式的车道条仍是原来的 `y=100/114`、`H=30`，不受影响。

## 实机看什么

进导航、等路口放大图浮窗出现后确认：车头白色三角的尖端是否比上一版露出更多、
下方是否能看到一线引导路线；如果仍觉得偏挡，继续把 `CROSS_LANE_Y` 往小调
（每减 4~6px 多露一点，代价是胶囊再往图里压一点）。
